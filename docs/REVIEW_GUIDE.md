# REVIEW가 남았을 때 확인할 내용

실행이 끝나면 `summary.txt`에서 최종 결과를 확인하고, 같은 실행 폴더의 **`review.tsv`**에서 원인과 권고 조치를 확인합니다. 실행하는 매크로는 계속 **`MB_01_RunBackup` 하나**입니다.

`review.tsv`는 이번 실행 중 관측된 경고·오류를 설명하는 보고서입니다. 어떤 경고는 뒤에서 복구되어 해결됐을 수 있고, 같은 메일의 여러 검사 단계가 각각 기록될 수 있습니다. 따라서 **보고서의 행 수는 현재 미해결 메일 수와 같지 않습니다.** 최종 `PARTIAL`, `FAILED`, 미처리·검토 건수와 함께 읽어야 합니다. 보고서 생성 이후 마무리 단계에서 발생한 오류는 최종 요약에 표시됩니다.

## 어디에서 찾나요?

새 기본 구성에서는 선택한 기준 폴더 아래 다음 상대 위치에 있습니다.

```text
MailBackup\State\runs\<실행 ID>\summary.txt
MailBackup\State\runs\<실행 ID>\review.tsv
```

기존 운영 이름을 이어 쓰는 아카이브는 해당 운영 폴더의 `runs` 아래에 있습니다. `summary.txt`의 **Review guidance** 항목에 실제 보고서 경로를 표시합니다.

TSV는 메모장이나 Excel에서 열 수 있습니다. 제목·경로·사유의 탭과 줄바꿈, `%` 등은 한 행의 구조를 보존하기 위해 escape되어 있습니다. 예를 들어 `%09`는 탭, `%0A`는 줄바꿈, `%25`는 문자 `%`를 뜻합니다. 제목은 메일별 검토 이벤트가 제공한 경우에 기록되며, 파일 또는 전체 운영 상태에 관한 이벤트에는 비어 있을 수 있습니다.

보고서는 `review.partial.tsv`에 기록한 뒤 닫기·flush가 완료되면 `review.tsv`로 게시합니다. 실패하면 기존 파일과 부분 보고서를 보존하고 최종 요약에 실패를 표시합니다. 보고서를 만들지 못한 상태를 정상 완료로 처리하지 않습니다.

## 원인 코드별 확인 순서

| 코드 | 의미 | 확인할 내용 |
| --- | --- | --- |
| `HISTORY_CUTOFF` | 기존 파일과 대응되지 않는 메일의 날짜가 기존 아카이브 최신 파일 수정 시각보다 오래됨 | 해당 제목을 기존 MSG에서 검색하고 계정 폴더가 맞는지 확인합니다. **미백업이 확인된 개별 메일**은 아래 절차에 따라 MSG를 한 번 저장하고 같은 매크로의 검증을 받을 수 있습니다. 확인되지 않으면 원본과 보고서를 보존합니다. |
| `LEGACY_UNREADABLE` | 기존 MSG의 파일명·발송 시각 등을 읽지 못해 대응을 확정하지 못함 | 드라이브 연결을 확인하고 표시된 MSG를 Outlook에서 열어봅니다. 손상됐다면 현재 파일을 보존한 뒤 정상 백업 사본과 비교합니다. |
| `CANDIDATE_LIMIT` | 같은 제목 등으로 가능한 후보가 많아 확인 한도에 도달함 | 후보의 발신자·일시·본문·첨부를 비교합니다. 제목이나 Message-ID 하나만으로 동일하다고 결론 내리지 않습니다. 후보 수를 줄이려고 기존 파일을 삭제하지 않습니다. |
| `FILE_MISSING` | 인덱스가 가리키는 기존 MSG를 찾을 수 없음 | 오프라인 드라이브를 연결하거나, 정상 백업에서 기록된 위치의 원본을 복원한 뒤 다시 실행합니다. 인덱스와 복구 기록을 지우지 않습니다. |
| `FILE_CHANGED` | 기존 파일의 크기·해시가 과거 기록과 다름 | 현재 파일을 별도로 보존하고 정상 백업과 비교합니다. 현재 파일의 해시로 과거 기록을 덮어쓰면 안 됩니다. |
| `PROOF_CONFLICT` | 서로 다른 파일·기대 바이트 증거가 충돌함 | 양쪽 파일과 기록을 모두 보존하고 출처를 확인합니다. 한쪽 기록을 삭제하거나 수동 병합해서 충돌을 숨기지 않습니다. |
| `REVISION_CONFLICT` | 공급자가 같은 버전으로 표시하지만 내용과 기존 파일 증거가 맞지 않음 | 원본 메일과 기존 MSG를 비교하고 양쪽을 보존합니다. Outlook 동기화·가져오기·수정 이력도 확인합니다. |
| `CONTENT_LIMITED` | 특수 첨부나 사용자 속성의 동일성을 현재 비교 범위로 충분히 입증하지 못함 | Outlook에서 원본과 저장 MSG의 관련 내용을 직접 확인합니다. 수동 확인만으로 프로그램의 지원 범위가 확대되거나 REVIEW가 자동 해소되지는 않습니다. |
| `IDENTITY_UNCERTAIN` | 가져오기 등으로 ID·일시 관계가 달라져 동일 메일 여부가 불명확함 | 제목, 발신자, 일시, 본문, 첨부와 올바른 계정 폴더를 확인합니다. 원본 메일을 보존합니다. |
| `MATCH_UNPROVEN` | 기존 MSG와의 대응을 검증하지 못함 | 원인 열과 표시된 계정 폴더를 확인하고 동일 제목의 기존 파일을 비교합니다. “찾지 못했다”를 “백업이 없다”로 바로 판단하지 않습니다. |
| `SOURCE_CHANGED` | 목록 수집·검사 중 원본이 수정·이동되거나 유형이 달라짐 | Outlook의 편집·이동·동기화가 끝난 뒤 같은 매크로를 다시 실행합니다. |
| `DOWNLOAD_REQUIRED` | 원본이 헤더만 내려받아진 상태 | Outlook에서 메일과 첨부를 완전히 다운로드한 뒤 다시 실행합니다. |
| `CURRENT_BASELINE` | 과거 무결성 증거가 없는 읽을 수 있는 MSG를 현재 바이트 기준으로 등록함 | 현재 상태를 기록한 결과입니다. 과거 원본과 동일했다는 증거는 아니므로, 과거의 정상 사본이 있다면 별도로 비교합니다. |
| `SCAN_FALLBACK` | 폴더 목록을 다른 경로로 다시 수집함 | 최종 폴더 실패·스캔 문제 건수를 확인합니다. 느린 경로로 정상 완료됐을 수도 있습니다. 실패가 남으면 Outlook에서 폴더를 사용할 수 있게 한 뒤 다시 실행합니다. |
| `STATE_REVIEW` | 인덱스·단계 기록·검사 상태 등에 검토할 문제가 있음 | 운영 폴더와 복구 폴더, MSG를 함께 복사하여 보존한 뒤 표시된 기록을 확인합니다. 다른 실행 시점의 상태 파일 하나만 덮어쓰는 방식은 피합니다. |
| `OPERATION_FAILED` | 파일·디스크·권한·Outlook 작업이 실패함 | 원인 열의 구체 오류를 해결하고 다시 실행합니다. 작업 실패의 원인이 해결될 때까지 기존 파일과 기록을 보존합니다. |
| `REVIEW_REQUIRED` | 위 코드로 좁히지 못한 경고 | 원문 사유와 최종 요약을 함께 확인합니다. 이후 단계에서 해결된 경고인지 먼저 구분합니다. |

## 기존 MSG가 있는데 과거 메일이 계속 보류돼요

기존 파일의 수정 시각은 메일의 발송·수신 시각과 다릅니다. 복사·복원 도구 등의 동작으로 파일 수정 시각이 최근으로 바뀌면, 백업된 적 없는 과거 메일도 `HISTORY_CUTOFF`에 해당할 수 있습니다.

먼저 제목과 계정 폴더를 기준으로 기존 MSG를 찾아 비교합니다. 그래도 대응 파일을 확인할 수 없다면 원본 메일을 계속 보존해야 합니다. 이번 버전은 이 상황을 보고서로 설명하며, 임의로 보호 조건을 해제하여 재내보내지는 않습니다. 인덱스 삭제·날짜 변경·파일 삭제로 조건을 우회하면 과거 증거를 잃거나 중복 백업을 만들 수 있습니다.

### 미백업이 확인된 개별 메일을 해소하는 절차

이 절차는 **`HISTORY_CUTOFF`이고, 기존 MSG 검색·계정 확인을 마쳐 해당 메일을 백업한 적이 없다는 판단이 가능한 경우**에만 사용합니다. 기존 파일의 해시 불일치, 파일 누락, 서로 충돌하는 증거를 해결하는 절차로 사용하지 않습니다.

1. 매크로가 끝난 상태에서 클래식 Outlook의 해당 **원본 메일**을 엽니다. 메일과 첨부가 완전히 내려받아져 있는지 확인합니다.
2. **파일 → 다른 이름으로 저장**에서 **Outlook 메시지 형식 - 유니코드(`.msg`)**를 선택합니다. 이 백업에서 선택한 **해당 계정의 MSG 보관 폴더**에 사용하지 않은 이름으로 한 번 저장합니다. 예를 들어 제목을 담은 `Manual_제목.msg`처럼 기존 파일과 겹치지 않게 합니다. 운영·복구 폴더 안에 저장하거나 기존 MSG를 덮어쓰지 않습니다. 클래식 Outlook의 저장 메뉴와 유니코드 설정은 [Microsoft 안내](https://support.microsoft.com/ko-kr/outlook/mail/save-an-outlook-message-as-a-eml-file-a-pdf-file-or-as-a-draft)의 클래식 Outlook 절을 참고하세요.
3. 원본 메일과 기존 파일을 그대로 둔 채 **`MB_01_RunBackup`**을 다시 실행합니다. 수동으로 저장한 MSG도 계정 폴더의 기존 파일로 수집됩니다. 파일명만으로 동일하다고 판단하지 않고 실제 발송 시각으로 후보를 찾은 뒤 본문·수신자·첨부·지원하는 메타데이터와 파일 해시를 검증합니다. 정상적으로 읽을 수 있고 정리 조건을 만족하면 연/월 폴더 정리 대상에도 포함됩니다.
4. 최종 요약과 새 `review.tsv`를 확인합니다. `events.tsv`에서 해당 `source_key`의 `LEGACY_LINKED_NO_SAVEAS`가 기록되면 검증한 MSG가 기존 파일로 연결된 것입니다. 추가 후보 충돌, 후보 한도, 원본 변경, 특수 첨부·사용자 속성 등으로 실제 동일성이 입증되지 않으면 **REVIEW를 유지**합니다. 같은 메일을 반복해서 수동 저장하면 후보만 늘어날 수 있으므로, 원인이 남은 상태에서는 새 사본을 더 만들지 않습니다.

이 과정에서 프로그램이 다시 SaveAs하여 해소하는 것은 아닙니다. 사용자가 제공한 개별 MSG를 기존 파일 검증 경로로 등록합니다. 수동 저장했다는 사실이나 눈으로 확인했다는 사실만으로 검사 결과를 성공 처리하지 않습니다.

## 결과를 판단하는 기준

- `review.tsv`가 생성됐다는 사실은 백업 전체가 완료됐다는 뜻이 아닙니다. 최종 요약의 상태와 미처리·실패·검토 건수를 확인합니다.
- 기존 파일을 재사용했다면 새로 SaveAs하지 않았다는 결과와 내용 검증 범위를 함께 확인합니다.
- `MSG_ONLY_REBASELINED`는 현재 바이트의 기준선입니다. 사라진 과거 해시를 복원했다고 해석하지 않습니다.
- `review.tsv`를 편집하거나 삭제해도 재시도 의무, 완료 시각, 검토 결과는 해소되지 않습니다. 프로그램은 이 보고서를 복구 증거로 읽지 않습니다.
- 보고서에는 메일 제목·사용자 경로·식별자가 들어갈 수 있습니다. 다른 사람에게 제공할 때는 필요한 행만 복사하고 식별 정보를 가린 뒤 공유합니다.

이 안내와 분류의 자동 검사는 Python 모델·소스 계약입니다. 실제 Outlook에서의 보고서 생성·파일 게시와 사용자 메일 검증은 별도 대상 환경 확인이 필요합니다.
