# v3.5.1 최종 검토 및 인수인계 — 2026-11-12

## 최종 판정

**저장소에서 수행할 코드·문서 검토와 배포 정리를 완료했습니다.** 새 코드 차단 결함은 발견하지 못했고, 605개 자동 검사를 같은 배포 파일로 다시 통과했습니다. 최종 점수는 **88.01/100(반올림 88점)**을 유지합니다. 실제 Windows 클래식 Outlook에서의 컴파일·native 검사·실제 MSG·10만 건 성능은 여전히 `NOT_RUN`입니다.

이번 변경은 캐시 발행 시점에 관한 설명 보완과 검토·인수인계 기록입니다. **BAS, 소스, 테스트, 검증 도구와 버전은 변경하지 않았습니다.** 검토를 반복했다는 이유로 점수를 높이거나, 미실행 검사를 완료로 바꾸지 않습니다.

## 이번 설명 보완 F01 — P3, 해결

캐시는 그 발행 시점까지 확인된 오류·취소·미처리가 있으면 새로 발행하지 않습니다. 그러나 실제 마무리 순서는 다음과 같습니다.

1. 메일 저널·이벤트 스트림 종료와 REVIEW 보고서 작성.
2. current-mail coverage/reconcile 오류를 확인하고 최종 상태에 반영.
3. 조건을 충족하면 optional selection cache 게시.
4. 마지막 snapshot 작성, 잠금 해제, 최종 요약 기록.

따라서 **3번 이후에 오류가 발생하면 `FAILED`와 이미 게시된 유효 캐시가 함께 남을 수 있습니다.** 캐시는 성공 coverage를 갱신하지 않으며, 다음 실행에서도 루트·StoreID·계정·시간대·정책·이전 성공 UTC와 coverage/journal/source-audit 해시를 모두 다시 확인합니다. 코드 결함이나 기존 메일 누락 경로로 판정하지 않았습니다.

README·시나리오·실제 Outlook 시험 절차·변경 이력의 표현을 발행 시점 기준으로 맞췄습니다. PR 설명에도 같은 구분을 적용합니다. 근거는 `mb_main.basfrag::MB_Run`과 `mb_selection.basfrag::MBW_CanSaveSelection`, `MBW_SaveSelectionCache`, `MBW_ApplySelectionCache`입니다.

최종 결과는 팝업과 `summary.txt`에서 확인합니다. `review.tsv`의 행 수, `.cache` 존재 여부, metadata 복구의 DONE 하나만으로 전체 백업 완료를 판정하지 않습니다.

## 남은 경계와 대상 PC 인수 확인

- 기본 저장소 `DefaultStore`의 일반 MailItem이 대상입니다. 모든 별도 PST·공유 저장소를 자동 포함하지 않습니다.
- MBS2/MBS3 기존 출력을 새 버전에서 읽고 검증해 재사용합니다. 새 MBS4 상태를 이전 작성기로 교대해서 쓰는 방식은 지원하지 않습니다.
- 모든 운영 증거가 사라지면 현재 MSG의 바이트를 관측할 수 있을 뿐, 사라진 과거 해시·역사를 복원했다고 인증할 수 없습니다. metadata 복구가 삭제된 MSG나 디스크 내용을 복원하지 않습니다.
- 신규 제목은 전체 경로 235 UTF-16 단위 예산 안에서 유지합니다. 잘린 부분을 Everything의 파일명 검색으로 찾을 수는 없습니다.
- 불명확한 과거 메일, 특수 첨부·사용자 속성, 충돌 증거는 REVIEW가 남을 수 있습니다. 캐시가 이 판단을 해소하지 않습니다.
- 전체 metadata 목록 순회와 과거 metadata 구간의 해시 비용은 유지합니다. 10만 개 합성 모델은 실제 Outlook 경과시간·메모리 측정이 아닙니다.
- 큰 파일 또는 느린 저장소의 한 번의 해시 작업 중에는 취소 반응이 늦을 수 있습니다. 현재 안전 단위가 끝날 때까지 기다리며 VBA `End`/`Reset`으로 중단하지 않습니다.

남은 인수 확인은 [실제 Outlook 검증 절차](OUTLOOK_VALIDATION.md)에 따릅니다. **가져오기·Compile → 자동 native 자체 검사 → 대표 기존 MSG 및 재실행 → 운영 기록 복구·재가져오기 → 실제 10만 건 측정**의 증거를 BAS SHA와 함께 남겨야 합니다. 공개 저장소에 실제 메일 제목·개인 경로·식별자가 담긴 원본 실행 로그를 올리지 않습니다.

## 사용자가 실행할 것

1. 위 v3.5.1 BAS 한 파일을 받습니다. 같은 모듈이 있다면 기존 모듈을 내보내 보관한 뒤 교체합니다.
2. Windows 클래식 Outlook의 VBA 편집기에서 `Debug > Compile VBAProject`를 확인하고 저장합니다.
3. **`MB_01_RunBackup` 하나를 실행합니다.** 각 VBA 세션의 첫 실행은 비공개 자체 검사를 자동 수행합니다.
4. 선택이 필요하면 기존 MSG가 들어 있는 계정 폴더를 지정합니다. 경로를 확인해 기억하며, 이후 같은 매크로를 사용합니다.
5. 최종 팝업·`summary.txt`를 확인하고 REVIEW가 남으면 같은 실행 폴더의 `review.tsv`와 [해소 안내](REVIEW_GUIDE.md)를 확인합니다.

SafeV2를 먼저 실행하거나 별도의 01·02·03 매크로 순서를 진행할 필요가 없습니다. 확인 가능한 기존 MSG 전체를 다시 내보낼 필요도 없습니다.
