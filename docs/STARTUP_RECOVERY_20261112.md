# v3.5.2 — 시작 검사 오류 수정과 자동 복구

## 결과와 범위

2026-11-12 사용자 보고 `fail; failed checks=1, remain NOT_RUN`에 대응하여 **MAPI 오류값 처리 결함을 수정하고, 백업 전 자체 검사의 제한된 자동 복구를 추가**했습니다. 사용자에게 실패 행 복사를 요구하는 대신 팝업에 검사명·상세 사유를 표시하고 로컬 텍스트 보고서를 자동으로 여는 방식을 사용합니다.

사용자가 실제 가져온 모듈 버전, 실패 검사명, 오류 번호와 `acceptance.tsv`는 확보하지 못했습니다. 따라서 아래 코드 결함은 확인된 사실이지만, 보고된 실패와의 직접 일치는 **미확인**입니다. 이전 검토의 점수나 Python 검사 통과를 실제 Outlook 통과로 해석하지 않습니다.

## 확인된 결함

기존 `MBL_PropertySelfTest`, `MBE_CategorySelfTest`, 운영 중 누락 속성을 판별하는 `MBL_MissingProperty`에는 `CVErr`에 음수 MAPI HRESULT를 넘기는 호출이 있었습니다. `&H8004010F`는 MAPI의 속성 없음, `&H80070005`는 접근 거부에 해당하는 32비트 오류값입니다.

[Microsoft MS-VBAL의 CVErr 규정](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/7a7facef-2f52-4d08-918e-63bf6a9261ed)은 숫자 인수가 0~65535를 벗어나면 VBA 오류 5를 발생시키도록 정합니다. 이 결함은 진단 폴더를 지우거나 같은 코드를 다시 실행하는 것으로 해결되지 않습니다.

수정본은 초기화된 로컬 Error Variant의 SCODE 4바이트만 읽고 씁니다. 읽기 전에 값과 실제 저장 타입을 확인하며, BYREF·배열 형식이나 외부 포인터를 따라가지 않습니다. 전체 32비트 HRESULT를 유지하므로 접근 거부, 다른 오류 영역, 하위 16비트만 같은 값을 “속성 없음”으로 취급하지 않습니다. 근거는 [Windows VARIANT 구조](https://learn.microsoft.com/en-us/windows/win32/api/oaidl/ns-oaidl-variant)와 [Error 값의 구현별 변환 규정](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/c86480b2-aef2-4488-b177-f55e13cc51f2)입니다.

## 자동 복구의 동작

1. `MB_01_RunBackup`은 미정리 잠금·스트림·해시 객체·임시 저장 예약이 없는지 확인합니다.
2. 새 보고서와 일회성 검사 파일을 만듭니다. 보고서는 LOCALAPPDATA, 검사 파일은 TEMP를 우선하며, 사용할 수 없으면 다른 후보를 확인합니다. 경로의 연결 폴더 여부와 쓰기 가능 여부를 확인합니다.
3. 원래 자체 검사 전체와 자원 정리 검사를 실행합니다.
4. 실패했어도 취소되지 않았고 자원이 정상 정리됐다면, 위치 우선순위를 바꾸고 새 파일로 한 번 더 검사합니다. **최초 시도 포함 최대 2회**입니다.
5. 모두 통과하면 같은 명령에서 백업을 이어갑니다. 실패가 남으면 실제 백업을 시작하지 않고 검사명·상세 사유를 표시합니다. 작성 가능한 경우 마지막 보고서 폴더의 `startup.txt`에 두 시도의 결과를 보존하고 메모장으로 엽니다.

현재 세션에서 자체 검사에 이미 통과했어도 실제 백업을 시작하기 전에는 자원 상태를 다시 확인합니다. 진단 파일 닫기가 실패한 경우에도 통과를 취소합니다. 정리 미완료 상태는 Outlook 재시작 안내로 연결하며, 소유권을 알 수 없는 핸들을 강제로 초기화하지 않습니다.

## 보존하는 데이터

자동 복구는 기존 보고서, 실제 `State`·`_Recovery`, 경로 설정, 기존 MSG를 삭제하거나 초기화하지 않습니다. 검사에서는 원본 메일을 읽거나 변경하지 않고, 새 합성 미발송 메일과 직접 생성한 일회성 파일만 사용합니다. 원본 Outlook 메일에 `Delete`, `Move`, `Save`, `Send`를 실행하는 복구 경로를 추가하지 않았습니다.

새로 확보한 검사 폴더와 예약한 임시 파일의 정리는 기존 소유권 범위에서만 수행합니다. 실패한 검사 결과는 새 성공 결과로 덮어쓰지 않습니다. 해시·내용·복구 검사를 건너뛰어 성공으로 처리하는 경로도 없습니다.

`OutlookMailBackupValidation`은 검사 보고서 폴더이므로 **검사가 실행 중이 아닐 때 삭제해도 원본 메일이나 실제 MSG 백업에 영향을 주지 않습니다.** 다음 자체 검사에서 다시 만듭니다. 이미 성공한 현재 VBA 세션에서는 검사를 반복하지 않을 수 있습니다. 코드 결함을 고치려면 이 수정 BAS로 교체해야 합니다.

## 시나리오별 결과

| 상황 | 처리 | 실제 백업 시작 |

| 처음부터 검사 통과 | 자원 정리와 진단 파일 닫기 확인 | 예 |

| 진단 폴더만 삭제됨 | 다음 자체 검사에서 새 폴더 생성 | 모든 검사 통과 후 |

전체 VBA 프로젝트 컴파일, 실제 기존 아카이브 호환성, 모든 특수 MAPI·첨부파일, 10만 건 성능의 네 항목은 계속 별도 `NOT_RUN`입니다. 자동 재시도는 이 항목을 PASS로 바꾸지 않습니다.

## 검증 증거

- 모델·소스 계약 **610/610**, 검증기 결함 주입 **47/47**: 총 **657개**. 새 검사는 HRESULT 21개와 시작 복구 31개입니다.
- VBA7 32비트·64비트 및 Legacy 32비트 구조 검사: 각 537개 프로시저, 공개 실행 매크로 1개, 검출 오류 0.
- 추가 ANTLR 검사: 각 조건 분기에서 새 프로시저 16개·변경 프로시저 11개·전체 선언부, 합계 28단위에 문법 오류 0. 변경하지 않은 전체 프로시저를 다시 파싱한 결과는 아닙니다.
- 대상 BAS: **749,746 bytes**, **14,765 lines**, ASCII/CRLF.
- SHA-256: `7e8d6ee1db2d0067244fd384d42f3dce1d2f50275a664d713f5789540b1127d8`.
- [현재 검증 JSON](validation.json), [검증 설명](VALIDATION.md), [실행 로그](evidence/verify-v3.5.2-20261112.txt).

위 검사는 실제 Microsoft VBA 컴파일·Outlook COM/MAPI 실행을 대체하지 않습니다. **v3.5.2의 대상 PC 실행은 NOT_RUN**이며, 새 BAS를 가져와 컴파일한 뒤 `MB_01_RunBackup`으로 확인해야 합니다. 실제 오류가 계속되면 이제 팝업 또는 자동으로 열린 메모장의 화면 캡처만으로 다음 진단을 진행할 수 있습니다.

## 교체와 후속 확인

기존 모듈을 보관한 뒤 새 `OutlookMailBackup.bas` 한 파일을 가져오고 `Debug > Compile VBAProject`를 실행합니다. 이후 사용자가 실행할 매크로는 계속 **`MB_01_RunBackup` 하나**입니다. `CLEANUP_PENDING` 안내가 남으면 Outlook을 완전히 종료했다 다시 연 뒤 실행합니다. 기존 MSG나 설정 폴더를 지우는 설치 절차는 없습니다.

현재 작업은 `feat/v3.5-clean-layout-20261111` 브랜치와 draft PR #1에서 이어갑니다. main의 이전 배포본과 혼동하지 않도록 이 브랜치의 새 BAS를 사용합니다. main 병합은 수행하지 않습니다.
