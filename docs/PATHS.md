# 폴더와 경로 설계 — v3.5

새 설치는 **MailBackup / State / _Recovery**라는 역할 이름을 사용합니다. 사용자 PC의 드라이브 이름이나 출력 폴더를 코드에 고정하지 않습니다. 실행할 매크로는 계속 `MB_01_RunBackup` 하나입니다.

## 새 폴더 구성

| 기준 | 상대 위치 | 역할 |
| --- | --- | --- |
| 선택한 기준 폴더 | `MailBackup\` | 관리 루트, 소유권·저장소 연결, 실행 잠금 |
| 관리 루트 | `State\` | 인덱스, 해시 증거, 이동·복구 기록, 검사 상태 |
| 관리 루트 | `State\runs\<실행 ID>\` | 해당 실행의 요약·로그·고정 작업 목록 |
| 선택한 계정 폴더 | `yyyy\mm\` | 실제 MSG 파일 |
| 선택한 계정 폴더 | `_Recovery\` | 운영 기록의 독립 스냅샷·청크·복구 계획 |
| Windows 사용자 로컬 데이터 폴더 | `OutlookMailBackup\locations\` | StoreID별 저장 위치 기억 |

기존 MSG가 계정 폴더에 평면으로 있거나 일부 하위 폴더에 있어도, 검증과 이동 계획을 거쳐 같은 `yyyy\mm` 구조에 정리합니다. `_Recovery`에는 MSG 사본을 만들지 않습니다.

## 경로를 저장하는 원칙

| 대상 | 저장 방식 | 이유 |
| --- | --- | --- |
| 새 MSG와 첨부 추출 파일의 경로 | 계정 루트 아래의 상대 경로 | 파일마다 전체 접두 경로를 반복하지 않음 |
| 기존 MSG의 신규 등록, 재가져오기 별칭 | 같은 상대 경로 계약 | 신규·기존·재가져오기 간 해석을 일치시킴 |
| 파일이 속한 계정 루트 | 체크섬 기록 안의 정확한 절대 경로 | 일부 기록만 복구돼도 다른 계정과 혼동하지 않음 |
| 선택한 기준·관리·계정 폴더 위치 | 사용자 설정·StoreID별 위치 파일의 절대 경로 | 다음 실행에서 실제 저장 위치를 찾음 |
| 이동 이력·이전 복구 증거·소유권 표식 | 기존 정확한 절대 경로 계약 유지 | 이미 기록된 증거를 이름 변경 때문에 재작성하지 않음 |

예를 들어 파일 경로 필드는 `2026\11\20261111_091500_sender_제목.msg`가 됩니다. 실제 디스크 작업에서는 계정 루트를 앞에 결합해 전체 경로를 얻습니다. 파일 경로가 상대화되어도 각 기록에는 계정 루트 바인딩이 한 번 남습니다.

이 방식은 **절대 경로의 불필요한 반복과 PC별 하드코딩을 줄이는 변경**입니다. 계정·복구 메타데이터 전체를 위치 독립 형식으로 바꾼 것은 아닙니다. 아카이브 전체를 임의로 다른 드라이브로 옮기는 기능은 별도 검증·이관 절차가 필요합니다.

## MBS4 읽기·쓰기 계약

새 저널 행은 원래 직렬화 문자열의 체크섬을 먼저 검증합니다. 상대 경로를 해석한 절대 경로는 메모리 안에서만 사용하며, 읽었다는 이유로 기존 원문이나 체크섬을 바꾸지 않습니다.

| 기록 종류 | MBS4 디스크 형식 | 메모리에서 사용하는 기존 계약 |
| --- | --- | --- |
| N / T / R | 17필드, 상대 파일 경로 + 계정 루트 | MBS3의 절대 파일 경로 계약 |
| L | 17필드, 상대 파일 경로 + 계정 루트, 중복 루트 필드 없음 | MBS2 L의 16필드 계약 |
| 기존 MBS2 / MBS3 | 기존 형식 그대로 | 기존 형식 그대로 |

N은 신규 MSG, T는 선택적으로 추출한 첨부파일, R은 검증된 기존 파일을 참조하는 별칭, L은 기존 MSG 등록입니다. 기본 설정에서는 첨부파일을 별도 추출하지 않습니다.

상대 파일 경로에는 절대 드라이브 경로, UNC, 앞의 구분자, `/`, ADS 구분자 `:`, 빈 구성 요소, `.`·`..`, Windows 예약 이름과 안전하지 않은 구성 요소를 허용하지 않습니다. 계정 루트 자체로 드라이브·공유 루트를 허용하지 않습니다. Unicode·이모지·문자 그대로의 `%09`는 기존 이름 정책 안에서 유지합니다. 모든 Unicode 제어 문자를 일괄 금지하는 정책은 아닙니다.

파일은 여전히 계정 루트 아래에 있어야 하며, 실제 파일 사용 시 재분석 지점 검사·기존 해시 검사·최종 파일 가드를 적용합니다. 상대 경로를 사용한다고 경로 길이 제한이 없어지는 것은 아닙니다.

## 이전 디렉터리 이름과 충돌

| 관리 루트 | 운영 폴더 | 계정의 복구 폴더 |
| --- | --- | --- |
| 새 `MailBackup` | `State` | `_Recovery` |
| 기존 `SafeV2` 또는 이전에 소유권이 확인된 사용자 지정 루트 | `_MailBackup_Data` | `_MailBackup_Recovery` |

전체 조합은 관리 루트의 이름으로 결정합니다. 설정·운영 폴더·복구 폴더가 삭제됐다는 이유로 다른 조합으로 바뀌지 않습니다. 이 이름 선택을 위한 새 설정 파일은 추가하지 않았습니다.

새 이름과 옛 이름에 각각 기록이 있거나, 선택한 계정에 두 복구 폴더가 함께 있으면 임의로 합치지 않습니다. 실제 선택한 계정의 기록을 검토해야 합니다. 관계없는 다른 계정의 폴더 이름만으로 현재 계정을 연결하지 않습니다.

새 MBS4 기록을 쓰기 전에 소유권 표식은 `OutlookMailBackup.Schema4`로 전환됩니다. 이전 작성기와 교대로 실행하지 않습니다. 기존 MSG를 재사용할 수 있다는 것과 이전 작성기가 새 운영 형식을 쓸 수 있다는 것은 별개입니다.
