# 실제 Outlook 검증 절차

이 저장소의 자동 검사는 Python과 소스 구조를 검증합니다. 아래 절차는 실제 클래식 Outlook과 MSG 공급자가 필요한 남은 검증입니다. 저장소 작성 환경에서 실행하지 않았으므로 완료 전에는 `NOT_RUN`입니다.

사용자가 실행하는 매크로는 **`MB_01_RunBackup` 하나**입니다. 별도의 순서별 매크로를 추가하지 않습니다.

## 1. 가져오기와 컴파일

Windows 클래식 Outlook의 VBA 편집기에서 기존 모듈을 보관한 뒤 새 BAS를 가져옵니다. `Debug > Compile VBAProject`로 전체 프로젝트를 컴파일하고 저장합니다. 오류가 있으면 오류 문구와 해당 프로시저를 기록하고 먼저 수정합니다. 새 Outlook과 Mac Outlook은 대상이 아닙니다. 매크로 실행 허용은 조직의 보안 정책을 따릅니다.

검증 기록에는 BAS SHA-256, Outlook 버전·32/64비트, Windows 버전·표시 언어·시간대를 남깁니다. Python의 Windows 검사 결과를 Outlook 컴파일 결과로 대체하지 않습니다.

## 2. 첫 실행 자체 검사

`MB_01_RunBackup`의 첫 실행은 현재 VBA 세션에서 임시 파일과 합성 미발송 메일을 검사합니다. 상대 저널 경로, 해시, 파일 이동, Gregorian/UTC, MAPI 속성, MSG 저장·재열기 및 메타데이터 복구를 다룹니다. 자체 검사에 실패하면 실제 아카이브 작업을 시작하지 않습니다.

검사 보고서는 사용자 로컬 데이터 폴더의 `OutlookMailBackupValidation\<실행 ID>\acceptance.tsv`에 기록됩니다. 합성 검사 통과 뒤에도 실제 아카이브 호환성과 대량 처리 등의 별도 항목은 `NOT_RUN`으로 남습니다.

## 3. 대표 아카이브 검증

실제 운영 백업을 변경하기 전에 복사한 소규모 아카이브와 테스트 Outlook 프로필에서 다음 순서를 확인합니다. 기본 저장소를 대상으로 하므로 테스트할 저장소가 그 프로필의 DefaultStore인지 확인합니다.

1. 평면·하위 폴더에 흩어진 기존 MSG를 가진 계정 폴더를 선택합니다. `yyyy\mm` 정리 후 파일 수·바이트 해시·제목을 확인합니다. 이름 충돌 시 원본이 덮어써지지 않아야 합니다.
2. 같은 매크로를 다시 실행합니다. 이미 확인된 기존 메일이 불필요한 신규 MSG로 늘어나지 않아야 합니다.
3. 일반 신규 메일, Unicode 제목, 긴 제목, 일반 첨부파일이 있는 메일을 추가합니다. 파일과 보고서의 NEW/REUSE/REVIEW 분류를 확인합니다.
4. 테스트 메일을 같은 StoreID에 다시 가져와 기존 MSG와 연결되는지 확인합니다. 다른 StoreID는 같은 계정으로 자동 연결되면 안 됩니다.
5. 테스트 메일의 본문·첨부·범주를 바꿉니다. 과거 파일을 보존하면서 새 리비전 또는 명시적 REVIEW가 나와야 합니다.
6. 실행 중 같은 매크로로 취소를 요청하고 정리를 기다립니다. 다음 실행에서 미완료 기록이 재개되며 완료되지 않은 항목을 성공으로 세지 않아야 합니다.

검토가 필요한 항목이 있으면 `PARTIAL`의 원인을 기록합니다. “파일이 생겼다”, “매크로가 끝났다”, “현재 선언 범위를 확인했다”를 같은 성공으로 취급하지 않습니다.

## 4. 운영 상태 삭제·충돌 검증

이 단계는 앞 단계와 분리한 테스트 복사본에서 수행합니다. 동작 중 파일을 지우거나 원본 운영 아카이브를 훼손하지 않습니다.

| 시험 | 기대 결과 |
| --- | --- |
| 사용자 설정만 제거 | 위치 파일·표식으로 복원하거나 폴더를 다시 선택 |
| `State` 일부·전체 제거 | `_Recovery`와 남은 기록으로 복구하고 현재 메일을 재조정 |
| `_Recovery`만 제거 | 살아 있는 활성 증거를 유지하고 새 복구 세대 구성 |
| 모든 운영 기록 제거, MSG 유지 | `MSG_ONLY_REBASELINED`; 과거 해시 복원으로 표시하지 않음 |
| 인덱스가 가리키는 MSG 변경·누락 | 검토 대상으로 유지, 자동 덮어쓰기·재기준화 금지 |
| 같은 키의 다른 기대 해시 기록 | 일반 로딩과 복구 양쪽에서 충돌 보존·중단 |
| 새 이름과 옛 이름의 서로 다른 상태 | 모호한 기록을 자동 선택·병합하지 않음 |

## 5. 실제 성능 확인

10만 건이라는 개수와 함께 총 바이트, 평균·최대 크기, 첨부파일 비중, 로컬/네트워크 저장소, 처음/반복 실행을 기록합니다. 초기 기존 MSG 등록과 이후 증분 실행은 비용이 다릅니다. NEW/REUSE 항목 시간과 목록 수집·해시·이동·복구·검사·최종 기록 시간을 각각 확인합니다.

보고서의 표본 추정은 같은 조건의 항목 처리 비용을 가늠하는 값입니다. 10만 건 전체 완료 시간을 실제로 재지 않았다면 `100000_ITEM_PERFORMANCE`를 PASS로 바꾸지 않습니다. 여러 번 실행한 결과에서 누락·중복·기존 해시 변화가 없는지도 함께 확인합니다.

## 완료 증거

컴파일 결과, 자체 검사, 각 시나리오 실행의 `summary.txt`, 입력·출력 파일 목록과 해시 비교, 실제 측정 조건·시간을 BAS SHA와 연결해 보관합니다. 이 보고서에는 메일 제목·개인 경로·식별자가 들어갈 수 있으므로 공개 저장소에는 식별 정보를 제거한 결과만 올립니다.
